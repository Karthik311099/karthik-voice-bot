# Project Summary: Karthik's AI Voice Proxy
Built for: 100x AI Agent Team Assessment

## 1. Project Overview
A high-performance, voice-interactive AI agent designed as a professional surrogate for Karthik Murugesan. The bot can discuss Karthik's technical projects, experience, and his alignment with the 100x mission using a natural, human-like voice.

## 2. Evolution Stages (Initial to Final)

### Stage 1: The Foundation
- Built with React (Vite) and Tailwind CSS for a modern, responsive UI.
- Integrated Groq (Llama 3.1 8B) for lightning-fast text reasoning.
- Setup secure backend proxying via Vercel Serverless Functions.

### Stage 2: Solving Input (STT)
- Problem: Native browser speech recognition was unreliable and dropped out.
- Solution: Implemented "Industrial-Grade" STT using MediaRecorder + Groq Whisper. This captures raw audio and transcribes it with 99% accuracy even in noisy environments.

### Stage 3: Solving Output (TTS)
- Problem: Mobile browsers played robotic female voices with high latency (30s delay).
- Solution: Switched to OpenAI Neural TTS (tts-1 model) using the 'Onyx' voice.
- Optimization: Implemented Direct Source Streaming and the Opus audio format. This reduced mobile voice delay from 30 seconds to near-instant playback.

### Stage 4: Knowledge Integration
- Scraped 100x.inc to teach the bot about "Nikolai," the AI CEO, and 100x's "Rules of Execution."
- Integrated Karthik's full resume, including projects like Multilingual Video Translation and RAG-based MediBot.

## 3. Technical Stack
- Frontend: React 19, TypeScript, Lucide React (Icons), Tailwind CSS.
- LLM: Groq (Llama 3.1 8B Instant).
- Speech-to-Text: Groq Whisper (Large-v3).
- Text-to-Speech: OpenAI Neural TTS (Voice: Onyx, Model: tts-1).
- Backend: Vercel Edge Functions (Node.js/TypeScript).

## 4. Interview "Deep Dive" Preparation

### Question: "What was the hardest technical challenge?"
Talking Point: "Mobile TTS Latency. Standard MP3 files caused a 30-second delay on mobile. I solved this by switching to the Opus format and implementing Direct Source Streaming. This allows the browser to start playing audio bits as soon as they arrive from the OpenAI API."

Talking Point: "Latency is the killer of voice UX. Groq's LPU (Language Processing Unit) delivers tokens fast enough to feel like a real-time conversation, which is essential for a voice-first agent."

### Question: "How does this align with 100x's mission?"
Talking Point: "100x focuses on 'Rules of Execution' and high-stakes automation. I built this bot with rigorous system prompting to ensure it remains professional and deterministic, demonstrating how AI can scale a person's presence (my proxy) while maintaining compliance and brand voice."

  ---

  1. Folder & File Breakdown
  The project is split into Frontend (Client) and Backend (Serverless API) for security and performance.

  Backend (The api/ folder)
  These are Edge Functions. They run in the cloud (Vercel) and handle secure tasks that you don't want the user to see (like API keys).
   * api/chat.ts: The "Brain." It connects to Groq (Llama 3.1 8B). It contains your System Prompt (the 100x knowledge + your resume). It manages the conversation logic.
   * api/transcribe.ts: The "Ears." It takes the raw audio recorded by your phone and sends it to Groq Whisper. It returns the text of what you said.
   * api/speak.ts: The "Voice." It connects to OpenAI TTS. It converts text into a high-speed Opus audio stream.
   * vercel.json: The "Map." It tells Vercel how to route traffic to your API functions.

  Frontend (The src/ folder)
  This is what the user sees and interacts with.
   * src/App.tsx: The "Orchestrator." This single file handles:
       * UI State: (Is it loading? Is it listening? Chat history?)
       * Mic Logic: Uses the browser's MediaRecorder API to capture audio.
       * Audio Priming: A technique to "unlock" mobile speakers on the first click.
       * Streaming Logic: Directs the <audio> element to play the voice as it downloads.
   * src/main.tsx & index.css: The "Foundation." They initialize React and load Tailwind CSS.

  ---

  2. The 100x Workflow (Data Flow)
  When you talk to the bot, this is what happens in milliseconds:

   1. Input (User Speak):
       * You click the Mic button.
       * The browser triggers MediaRecorder to start capturing audio.
       * Pro Tip: Simultaneously, the app "primes" the speakers to bypass mobile autoplay blocks.

   2. Transcription (STT):
       * The audio "Blob" is sent to /api/transcribe.
       * Groq Whisper processes it and returns text.

   3. Reasoning (LLM):
       * That text is sent to /api/chat.
       * The LLM compares your words against the 100x mission and your resume.
       * It generates a professional, conversational response.

   4. Speech (TTS):
       * The response text is displayed on the screen instantly (to reduce perceived latency).
       * In the background, the text is sent to /api/speak.
       * OpenAI generates the Opus audio.

   5. Output (Direct Stream):
       * The browser's <audio> element connects directly to the stream.
       * The voice starts playing while the file is still downloading, ensuring zero delay.
